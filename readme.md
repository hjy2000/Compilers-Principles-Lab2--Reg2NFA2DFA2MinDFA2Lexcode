# XLEX 词法分析程序生成器

编译原理实验二（华南师范大学）——正则表达式 → NFA → DFA → 最小化 DFA → C 词法分析程序。

本仓库在原始提交（`temp.py` / `main.py`，2022 年版本）的基础上重写了主程序，补齐了
原版本未完成与有缺陷的部分。原文件保留不动作为历史版本；新主程序为 **`xlex.py`**。

---

## 1. 快速开始

```bash
# 启动图形界面（推荐用启动脚本，它会自动挑选 Tk 版本够新的 Python）
./run.sh

# 也可以直接跑；在 macOS 上若检测到 Tk < 8.6 会自动换解释器重试
python3 xlex.py

# 命令行：打印 NFA / DFA / 最小化 DFA 三张状态转移表
python3 xlex.py --regex '(a|b)*abb' --dump

# 命令行：用最小化 DFA 切分文本
python3 xlex.py --regex 'ab|c' --text 'ab c ab X c'

# 命令行：生成 C 词法分析程序
python3 xlex.py --regex '[a-zA-Z_][a-zA-Z0-9_]*' --emit-c scanner.c
cc -O2 -o scanner scanner.c
./scanner tests/sample_program.txt
```

只依赖 **Python 标准库**（`tkinter` 用于界面）。无需 `pandas` / `numpy` / `pythonds`，
也不用安装任何第三方包。

### macOS 用户请注意：Tk 版本

macOS 自带的 `/usr/bin/python3` 链接的是 **Apple 的 Tk 8.5**（2011 年的版本）。
它在 macOS 10.14 之后有已知缺陷：窗口能打开、标题栏正常，但**内容整片空白**。
这不是程序的问题，换成 Tk 8.6 及以上即可正常显示。

`run.sh` 会自动跳过 Tk 8.5 的解释器；`xlex.py` 在检测到 Tk < 8.6 时也会自动
尝试换一个解释器重新启动。若两者都失败，会打印安装指引。可用的安装方式：

```bash
# 方式一：uv（无需管理员权限，最快）
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.13

# 方式二：Homebrew
brew install python@3.13 python-tk@3.13

# 方式三：python.org 安装包（自带 Tk 8.6）
# https://www.python.org/downloads/macos/
```

检查当前解释器用的是哪个 Tk：

```bash
python3 -c "import tkinter; print(tkinter.TkVersion)"    # 需要 >= 8.6
```

本机（macOS 27 / Apple Silicon）实测：系统 Python 3.9.6 → Tk 8.5（界面空白）；
uv 的 Python 3.13.2 → Tk 8.6（界面正常）。

## 2. 支持的语法

| 语法 | 含义 | 示例 |
| --- | --- | --- |
| 单字符 | 可打印 ASCII 字符 | `a` `0` `_` |
| 连接 | 并列书写，或用 `.`、`·` 显式表示 | `ab` `a.b` |
| 选择 | 或 | `a\|b` |
| 克林闭包 | 零次或多次 | `a*` |
| 正闭包 | 一次或多次（选做） | `a+` |
| 可选 | 零次或一次（选做） | `a?` |
| 括号 | 分组 | `(ab\|c)*` |
| 字符集 | 枚举或区间（选做） | `[abc]` `[a-z]` `[0-9A-Z_]` |
| 空串 | ε 或 `~` | `a\|ε` |
| 转义 | 匹配元字符本身 | `\*` `\|` `\(` `\.` |

优先级（低 → 高）：`|` < 连接 < 后缀 `*` `+` `?` < 原子（括号、字符集、字符）。
后缀运算符不可连用（`a**` 会报错）。

## 3. 算法实现

### 3.1 正则表达式 → 语法树

递归下降分析器，文法为：

```
alt     -> cat ('|' cat)*
cat     -> repeat (('.'|'·')? repeat)*
repeat  -> atom ('*' | '+' | '?')*
atom    -> '(' alt ')' | '[' class ']' | '\' 字符 | 'ε' | 普通字符
```

连接运算无需预插 `.` 符号，由 `cat` 层自然处理相邻项。
所有语法错误都抛 `RegexError` 并带字符位置，界面弹窗提示而不是崩溃。

### 3.2 语法树 → NFA（Thompson 构造法）

对每种结点按 Thompson 规则生成片段，每片段返回 `(入口状态, 出口状态)`，
出口没有出边，因此可安全拼接：

| 构造 | 结构 |
| --- | --- |
| `a` | `s --a--> t` |
| `ε` | `s --ε--> t` |
| `[abc]` | `s --a,b,c--> t`（入口对集合内每个字符各一条边） |
| `XY` | X 的出口 `--ε-->` Y 的入口 |
| `X\|Y` | 新入口分叉，两出口 ε 汇合 |
| `X*` | 入口可跳过、出口可回到入口 |
| `X+` | 至少走一次 X，出口可回到 X 入口 |
| `X?` | 入口可直接跳到出口 |

`+` 与 `?` 直接在 NFA 层构造，不必先重写成 `XX*` / `X|ε` 的语法树。

### 3.3 NFA → DFA（子集构造法）

用 `frozenset` 作状态集的键，BFS 发现新状态并顺序编号（保证初态为 0）：

1. 初态 = `ε-closure({nfa.start})`；
2. 对每个状态集和每个字母，求 `ε-closure(move(T, a))`；
3. 未出现过的集合入队；最终每个 DFA 状态都记录其对应的 NFA 状态集。

字母表由 NFA 的所有转移字符**升序去重**得到。原实现从每个 NFA 状态逐个收集字符，
导致 `(a|b)*abb` 得到 `['a','b','a','b','b']` 这样的重复列。

### 3.4 DFA → 最小化 DFA（划分精化 / Moore 算法）

1. **补全**：缺失转移统一指向新加的死状态 `dead`；
2. 只保留从初态**可达**的状态；
3. 初始划分 `{终态} / {非终态}`；
4. 反复精化：同一块内的状态若在某个输入字符上转移到不同块，就继续拆分；
5. 合并后**删掉死状态所在的块**——它表示"任何输入都不接受"，去掉后这些转移
   即为错误转移，语言不变；
6. 按 BFS 重新编号，使初态为 0、表格从 `A` 开始。

### 3.5 最小化 DFA → C 词法分析程序

生成一份完整、**可直接用 `cc` 编译**的 C 程序，包含：

- `static const int TRANS[状态数][字符类数]` 二维转移表，`-1` 表示无转移；
- `static const int ACCEPT[状态数]` 终态标记；
- `char_class()`：字符 → 字符类下标的 `switch`，非字母表字符返回 `-1`；
- `match_longest()`：最长匹配，只在到达终态时更新 `best`，
  因此取到的是"停在终态的最长前缀"；
- `main()`：读整个文件或 stdin，逐段匹配并输出
  `<TOKEN, 词素, [起点,终点)>` 与 `<ERROR, 字符, pos=位置>`，末尾汇总 token/error 数。

原实现的 `genCode()` 生成的是 C 与 C++ 混写、无法编译的片段
（用了 `cout`、`str.size()`，`ch` 未定义，且全局字符串跨次调用累加）。

## 4. 图形界面

窗口分为三部分：

- **顶部**：正则表达式输入框，`回车` 即执行；`打开…` / `保存…` 读写 `.txt` 源文件；
- **中部**：`NFA 状态转移表` / `DFA 状态转移表` / `最小化 DFA 状态转移表` /
  `词法分析程序 (C)` 四个标签页。表格带列头、自动列宽，初态（蓝底）与终态（绿底）
  高亮，最小化表额外给出「对应 NFA 状态集」；
- **底部**：状态栏显示各阶段状态数与字母表。

按钮：`表达式 → NFA`、`NFA → DFA`、`DFA 最小化`、`生成 C 程序`、`一键执行`、`关于`。
所有按钮回调都包了异常处理，语法错误弹窗提示，不会让界面失效。

## 5. 测试

```bash
python3 -m unittest -v test_xlex                  # 全部 32 项
python3 -m unittest -v test_xlex.TestEquivalence  # 只跑语言等价性
python3 -m unittest -v test_xlex.TestCodegen      # 只跑 C 代码端到端
```

| 测试组 | 内容 |
| --- | --- |
| `TestEquivalence` | 穷举长度 ≤ 5 的全部字符串，要求 **NFA / DFA / 最小化 DFA 三者**接受结果完全一致；并用 `re.fullmatch` 作独立参照 |
| `TestStructure` | 状态数、字母表去重、最小化幂等、`+` `?` 语义、ε 的各种写法、表格行列长度一致 |
| `TestErrors` | 14 类非法输入必须抛 `RegexError` |
| `TestScan` | 最长匹配、错误恢复、空白跳过、`a*` 可匹配空串时不死循环 |
| `TestCodegen` | 生成 C 程序 → `cc -Wall -Wextra` 编译（要求零告警）→ 运行 → 与 Python 端结果逐行比对 |
| `TestGui` | 三张表真正填充、列头正确、初态/终态高亮落在正确行、语法错误弹窗、C 代码写入文本框 |

关键数值校验：`(a|b)*abb` 的 NFA 14 态 → 子集构造 DFA 5 态 → 最小化 **4 态**（经典结果）。

## 7. 本次补齐的问题清单

对照实验要求逐条核查后的修复记录：

| # | 原版本问题 | 现状 |
| --- | --- | --- |
| 1 | `checkStatus()` 空函数、`minDFA()` 只调用它，**DFA 最小化完全未实现** | 实现划分精化最小化，含死状态处理与不可达状态剔除 |
| 2 | `show_minDfaChart()` 是 `pass`，最小化表不显示（要求 5） | 第三个标签页展示最小化 DFA，含合并前的 NFA 状态集 |
| 3 | `nfa2DFA()` 不是真正的子集构造：`(a|b)*abb` 算出 20 个状态 | 子集构造正确，得 5 态，最小化后 4 态（要求 4） |
| 4 | `wordsChart` 有重复列（`['a','b','a','b','b']`） | 字母表升序去重 |
| 5 | 生成的 C 代码混用 `cout`、`str.size()`、未定义 `ch`，**无法编译**（要求 6） | 生成完整可编译 C 程序，`cc -Wall -Wextra` 零告警 |
| 6 | `stringCode` 是全局量，多次生成会累加 | 每次重新生成 |
| 7 | 只支持 `a-z` 单字符 | 支持可打印 ASCII、字符集、`+` `?`（选做项） |
| 8 | GUI 只有裸 `Treeview`，无列头、无最小化表（要求 3/4/5） | 三个带列头的表格页 + C 代码页 + 状态栏 |
| 9 | 要求(2)的「保存源程序」缺失 | 增加 `保存…` 按钮 |
| 10 | 全部状态放在模块级全局变量里，函数间靠 `global` 串联 | 类封装，无全局可变状态 |
| 11 | 依赖 `pandas` / `numpy` / `pythonds`，触发 dtype `FutureWarning` | 只用标准库 |
| 12 | 装饰性的 `priorities` 优先级表与手写中缀转后缀 | 递归下降直接构造语法树，语义更清晰 |
